# MD060 - table-column-style

Tags: table

Aliases: table-column-style

Parameters: style ("aligned", "any", "compact", or "tight"; default "any"), aligned_delimiter (boolean; default false)

This rule is triggered when the column separator pipe characters (`|`) of a GitHub Flavored Markdown table are used inconsistently.

## Rationale

Tables read more easily when the pipes follow one convention throughout. Picking a style and sticking to it keeps diffs small and columns visually scannable.

## Examples

The `aligned` style lines the pipes up vertically:

```markdown
| Character | Meaning |
| --------- | ------- |
| Y         | Yes     |
| N         | No      |
```

The `compact` style uses a single space on either side of every pipe:

```markdown
| Character | Meaning |
| --- | --- |
| Y | Yes |
| N | No |
```

The `tight` style uses no space at all:

```markdown
|Character|Meaning|
|---|---|
|Y|Yes|
|N|No|
```

## Configuration

The `style` parameter selects the convention to enforce:

* `any` - Each table may use any of the three styles, but must not mix them; the style that produces the fewest violations for a table wins
* `aligned` - Pipes must line up with the header row
* `compact` - Exactly one space on each side of every pipe
* `tight` - No space next to any pipe

Set `aligned_delimiter` to also require the delimiter row to line up with the header when using `compact` or `tight`.

## Notes

Pipe columns are compared by terminal display width, so wide (for example CJK) glyphs count as two columns and a table that looks aligned is treated as aligned. This matches markdownlint, which uses `string-width`.
